# 我的名片流程

本文件定義「我的名片」的正確流程。此流程只處理目前登入使用者自己的個人專屬名片，不處理 AI名片夾掃入的他人名片。

## 1. 入口

可能入口：

- 首頁第一顆功能按鈕「我的名片」
- LINE OA 關鍵字「我的名片」
- 圖文選單導向我的名片
- 設定頁「我的專屬名片」
- LIFF 編輯連結

所有入口都必須解析同一個目前登入 LINE UID，並導向同一張本人名片。

## 2. 基本規則

- 一個 UID 只能有一張本人名片。
- 我的名片不可讀取 AI名片夾中的通訊錄名片。
- 若目前 UID 已有本人名片，必須直接顯示或編輯該名片。
- 若目前 UID 沒有本人名片，應引導建立，不可只彈出提示後沒有下一步。
- 建立名片時可使用 LINE 頭貼與預設模板快速生成。
- 新用戶不應被強制跳註冊頁；應在首頁提示並由「我的名片」導入建立流程。

## 3. 資料讀取順序

讀取本人名片時應依序判斷：

1. 目前登入 LINE UID。
2. 是否有 `personal card` 或等價本人名片紀錄。
3. 是否有已認領並綁定此 UID 的名片。
4. 是否有舊系統遷移過來且可被此 UID 確認的本人名片。
5. 若皆無，進入建立流程。

禁止事項：

- 不可因姓名相同就抓取他人名片。
- 不可因電話相同就覆蓋目前 UID。
- 不可從 `scannedBy = currentUser` 的名片中挑一張當作本人名片。
- 不可 fallback 到 `admin` 名片當作本人名片。

## 4. 建立流程

若使用者尚無本人名片：

1. 首頁「我的名片」閃動提醒。
2. 使用者點擊後直接進入建立名片頁。
3. 提供至少兩種方式：
   - 用 LINE 頭貼與預設資料建立。
   - 上傳自己的名片或圖片建立。
4. 生成後寫入目前 LINE UID 的本人名片。
5. 回到我的名片預覽或編輯頁。

建立後不得同時產生多張本人名片。

## 5. 編輯流程

編輯頁應支援：

- 聯絡資料
- 編輯內容
- 數位名片
- 名片版型
- 封面圖片
- 服務說明
- 底部按鈕設定

底部按鈕儲存規則：

- 電話自動補 `tel:`
- Email 自動補 `mailto:`
- 網址必須是 `http://` 或 `https://`
- LINE 好友連結必須是可開啟格式
- 規格錯誤時不可儲存，需提示欄位與原因

## 6. 四種版本

我的名片可有四種版本：

- 標準版
- 滿版 / 海報版
- 正方版
- 影音版

靜態版本與影音版本必須分開：

- 關鍵字「我的名片」只顯示靜態版本。
- 關鍵字「影音名片」只顯示影音版本。
- 影音版的影片、縮圖、hero 設定不可覆蓋靜態版封面。

版型切換時，應更新目前選定版本，不可複製其他人的版本資料。

## 7. 分享與推播

「我的名片」在 LINE OA 聊天室中應能：

- 顯示目前使用者的名片。
- 若有多張靜態版候選，使用 Flex 選單讓使用者選擇版本。
- 顯示「編輯名片」與「顯示名片」等測試按鈕。
- 右上角分享按鈕應使用推薦好友同源的邀請分享邏輯。

推播 Flex 必須完整帶出：

- 封面或 hero
- 姓名
- 說明
- 底部按鈕
- 分享按鈕

## 8. 失敗處理

錯誤情境與處理：

- 找不到本人名片：導入建立流程，不只顯示錯誤。
- token 缺失：只針對必要讀取與新用戶建立放寬，不可放寬 admin 操作。
- share scope 不足：提示目前 LIFF 不支援分享，或改用可支援分享的 LIFF。
- 名片版本錯亂：停止儲存並提示 resolver 找不到正確版本。

## 9. 驗收

此流程上線前至少驗證：

- 使用者 A 點我的名片不會看到使用者 B 的資料。
- 從首頁、設定頁、LINE 關鍵字進入看到的是同一張本人名片。
- 尚無名片的新用戶點我的名片可直接建立。
- 靜態名片與影音名片互不覆蓋。
- 修改標準版不會改掉滿版、正方或影音版。
- LINE 聊天室推播的按鈕與後台設定一致。
