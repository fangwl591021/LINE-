# 平台商城架構草案

本文件定義 AI商脈系統的「平台商城」邊界。平台商城是平台統一上架、會員購買與點數折抵、合作店家履約或核銷的功能，不是店家自行上架的店家商城。

## 目標

- 讓任何已登入會員都可以在平台商城購買商品或服務。
- 會員可以使用自己的購物金 / gift_money 點數折抵商城訂單。
- 每件商品可自訂點數折抵規則，結帳金額必須依商品明細逐項計算後產生。
- 平台管理員統一管理商品、上下架、訂單與合作店家結算。
- 合作店家只作為供應、履約、核銷或結算對象，不擁有商品上架權限。
- 不破壞現有名片、AI 名片夾、店家點數收銀、收件匣、租戶年費訂單與獎金流程。

## 非目標

- 不把平台商城做成每個店家的獨立賣場。
- 不讓租戶或店長自行新增商城商品。
- 不使用現有 `orders` 表儲存平台商城訂單。
- 不重用店家點數收銀流程處理商城折抵。
- 不在商城第一階段處理複雜分潤、物流、發票或第三方金流。

## 角色

| 角色 | 商城權限 |
| --- | --- |
| 未登入訪客 | 可視需求允許瀏覽公開商品，但不可下單或折抵點數。 |
| 一般會員 | 可瀏覽商品、建立自己的訂單、使用自己的點數折抵、查自己的訂單。 |
| 租戶 / 店長 | 與一般會員相同；若同時是合作店家，只能核銷或履約被指派的訂單。 |
| 合作店家 | 可核銷或履約與自己相關的商城項目；不可上架商品。 |
| 平台管理員 | 可建立商品、上下架、管理訂單、指派合作店家、處理核銷與結算。 |

## 系統邊界

平台商城應使用獨立命名空間：

- action 名稱使用 `platformShop*` 或 `PlatformShop*`。
- D1 表格使用 `platform_shop_*`。
- 前端模組使用 `js/modules/platform-shop.js`。
- 內建平台商城保留獨立頁面與資料邊界；首頁「線上商城」依營運設定導向 AIWE 商城搜尋頁。

不得混入下列既有流程：

- `orders`：目前用於租戶年費、推薦人、安置、BV 與獎金計算。
- `store_point_cashier_logs` 與店家點數收銀：只用於店家對客戶的消費贈點 / 折抵。
- 收件匣優惠券：可作為核銷設計參考，但不應直接當作商城訂單。
- 名片與影音名片資料表：商城不得寫入名片 ownership 或 card version。

## 建議導入階段

### Phase 0：文件與合約

- 定義商城資料模型。
- 定義 action policy。
- 定義點數折抵與核銷規則。
- 不修改 runtime、不新增 migration、不部署。

### Phase 1：只讀商品目錄

- 新增平台商品資料表或臨時 JSON 商品來源。
- 新增商品列表與商品詳情 action。
- 商品管理僅限平台管理員。
- 尚不開放購物車、下單、點數折抵。

### Phase 2：購物車與訂單草稿

- 建立 `platform_shop_orders` 與 `platform_shop_order_items`。
- 使用 `idempotency_key` 或 `client_request_id` 防止重複建立訂單。
- 訂單狀態先以 `draft`、`pending_payment`、`cancelled` 為主。

### Phase 3：會員點數折抵

- 折抵只扣買家的點數。
- 每件商品先計算自己的可折抵上限，再加總為訂單折抵上限。
- 帳本事件綁定 `order_id`。
- 不扣店家點數、不扣操作費。
- 失敗時不可產生半套訂單或重複扣點。

### Phase 4：核銷與平台結算

- 支援服務券、課程券或合作店家現場核銷。
- 合作店家只能核銷指派給自己的訂單或憑證。
- 平台後台統計核銷、履約與結算資料。

## 首頁入口原則

目前首頁「線上商城」入口導向 AIWE 商城搜尋頁（`shop_id=78`）；內建平台商城頁保留供後續正式商城功能使用。

商品管理入口不得放在一般店家設定；應放在平台管理員可見的後台區塊。

## 風險

- 若使用現有 `orders`，會污染租戶年費與獎金計算。
- 若重用店家收銀，會混淆會員折抵與店家贈扣點。
- 若讓租戶上架，會變成店家商城，違反平台商城定位。
- 若點數折抵沒有冪等鍵，重送請求可能重複扣點。
- 若核銷沒有單次限制，服務券可能被重複使用。
