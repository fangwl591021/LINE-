# 業績歸屬日期、人工排序與試算預覽

- 需求：管理員可記錄、修改或撤回年費訂單的業績歸屬時間；只知道月份的歷史資料保留月份精度。原始建單及收款時間、既有成交與獎金紀錄均保留。
- 具備有效訂單快照或已核對資料的訂單，若收款及獎金狀態符合條件、尚無成交確認、獎金交易及對帳明細，仍可修改日期；確認或已有獎金／結算紀錄後鎖定。快照不等於簽署、推薦或資格已核實。
- 日期變更採附加事件、版本與冪等鍵；日期目前不自動納入正式結算，既有流程遇有效登錄日期須待核。人工排序草稿另保存依據及完整性聲明；候選不能證明歷史資料完整。
- 使用者確認推薦人資格自 2026 年 10 月起重新計數。符合完整資料及資格檢查的 115.10 版新約可依人工排序顯示受領人、金額及預估截止日；資料不足、既有交易影響、續約或其他制度保持待核。試算僅供預覽，不建立對帳、不確認、不核發或付款。
- 發布控制由 `0089_bonus_release_control.sql` 的事件表記錄，空表預設關閉；關閉時保留 GET 查詢，日期及排序 POST 回 `503 FEATURE_DISABLED`，寫入條件再次檢查開關。啟用必須另由具權限總管透過控制 API 明確操作，不因遷移或部署自動啟用；結果不明的排序送出保留原請求編號。
- 正式基準：`2d09ef4`；工作只在隔離副本進行。曾遭自動審核拒絕的完整檔案不得換管道重傳、改名繞過或藉新路由弱化既有權限、證據與重複保護。
- 驗證與發布：修改前 `npm run guard:before` 曾通過；修改後須依最終變更重跑完整 after guard，並核對授權、競態、草稿重試、瀏覽器與正式環境。隔離測試通過不等於已部署或正式結算可用；缺少必要驗證或遇審核阻擋不得部署。
