# 管理員店家搜尋身分衝突

- 需求：楊滄棋既有總管之舊、新 LINE 身分應可正常查詢管理資料；使用者確認這些紀錄屬於同一人，希望避免因身分重複而全面擋住。
- 基準：正式來源 fangwl591021/LINE- main fc483744f5c0794d898174de0089c4e025a3b6b0，before guard 通過。正式只讀核對米樂資料存在，楊的已登記舊、新 UID 與主總管紀錄有既存 active 連結；另有一般會員共用點數識別，不可由此推定其為總管。
- 變更：依使用者明確要求，例外僅限楊滄棋，以 LINE 官方驗證的當前 UID、該總管既有精確 UID、唯一原總管列與必要直接身分連結核實；其他總管或會員維持原判定。重新核對需要原子身分證明的寫入，不因錢包、名稱或前端文字自行擴權。前端不變。
- 保留：不更動 users、身分連結、錢包、會員角色、名片歸屬、母站點數或通知收件人；非上述已登記總管及真實衝突繼續拒絕。驗證使用合成資料與隔離測試，不使用楊先生 token、真人修改或送點。
- 測試與發布：檢查新舊身分、一般會員、偽造同名、連結衝突、DB 故障、並行變更與各讀寫路徑；完整 after guard、CI、Worker/Pages 版本及設定讀回。正式登入結果與模擬驗證分開報告。
- 只讀實證：以模擬 LINE 身分和正式 D1 唯讀查詢執行實際本機店家列表程式；楊已登記的舊、新 UID 均返回 200 且查到米樂 2 筆，另外兩個共用點數識別的 UID 均返回 409。未使用真人 token，也未異動正式資料。
- 本機驗證：收窄為楊滄棋後，160 項相關測試通過，涵蓋原子寫入時角色、連結、同組帳號資料變動，以及公開功能的權限邊界；其他現有總管衝突時維持拒絕。楊的例外在呼叫外部審核前另核對身分，D1 失敗或身分變更時不呼叫 provider。共創財務、AI 建檔與通知保持原有驗證，需另案處理；不宣稱這些功能已解除既有衝突。
