## 5. 退版觸發與執行順序

任一已確認的儲存遺失、按鈕連錯人、權限錯誤、分享／發送失敗，停止擴大開放並立即進入退版。若主要是視覺或使用成效不佳，由使用者決定切回；不在此輪建立自動監控或自行排程。

### A. 優先：功能開關切回舊版

1. 記錄事故與當前部署，暫停本功能後續發布，關閉新版名片開關。
2. 確認網頁、編輯、預覽、聊天室與分享同步回舊版，寫入保護仍啟用。
3. 核對名片資料未縮減、未換擁有者，其他功能仍正常。

### B. 開關無法解決：撤回新版程式

1. 在最新正式分支上，只撤回本次名片功能提交；保留其他功能與資料保護提交，不 reset／force-push 整站到舊 SHA。
2. 同步調整 cache version，跑相關測試與 guard，再以現有 GitHub Pages workflow 發布。
3. 後端有修改才處理 Worker：先判斷新版資料及 bindings 相容；優先發布撤回名片差異但保留資料保護的相容版本。
4. 只有在版本未混入其他更新、資料與 bindings 均相容、且不會讓舊儲存流程截掉按鈕時，才可選定上述 Worker 基準版本回退；不能無條件套用。
5. 預估完整程式重部署 5–15 分鐘，需演練確認，GitHub／Cloudflare 服務或權限問題可能延長。

Cloudflare 的 Worker rollback 不會還原 D1／R2 等資源，舊程式須相容現有資料；可回退版本及 bindings 也有限制。依 [Cloudflare 退版文件](https://developers.cloudflare.com/workers/versions-and-deployments/rollbacks/) 執行前重新核對。

## 8. 實際退版操作與驗收證據

後端使用現有 `app_meta` 的單一 key `feature:card-links-v2`，只有值 `enabled` 才啟用。無資料表異動、無 migration、無批次改寫名片。

在確認目錄為本 repo 且 D1 為 `actmaster_db` 後，管理員可執行：

```powershell
# 快速退版：只改一個功能開關，不還原資料庫
wrangler d1 execute actmaster_db --remote --command "INSERT INTO app_meta(key,value) VALUES('feature:card-links-v2','disabled') ON CONFLICT(key) DO UPDATE SET value=excluded.value;"
# 唯讀驗證應為 { enabled: false }
Invoke-RestMethod https://line-engine.fangwl591021.workers.dev/api/card-links/config
```
