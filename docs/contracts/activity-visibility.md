# 活動發布可見範圍

2026-10-08 使用者要求：上傳／發布活動時彈出選擇，公開則全網可見，不公開則歸屬可見。

- 「全網」沿用既有會員權限，指所有已登入、已註冊的平台會員，不是匿名網際網路訪客。
- 手機活動建立／修改、後台活動建立／修改／重新上架、會員辦活動確認發布／修改，送出前提供「是，公開」、「否，僅歸屬可見」與取消。取消不寫活動、不進行確認發布的附件上傳。選檔／AI 解析仍只產生草稿。
- `visibility` 僅接受 `platform` 或 `network`；「上架／下架」仍是獨立狀態，公開不會使下架活動可報名。
- 伺服器依既有已驗證會員身分取得歸屬網，不採用 URL/payload 的角色、UID、networkId 來授權新可見範圍。改可見性不更動會員推薦人、歸屬、活動主辦或點數。
- 同一範圍約束首頁／活動列表、直接明細、會員活動附件及新增／重新報名。官方公開活動只擴大公共目錄與讀取／報名，不擴大管理列表、編輯、簽到或名單權限。
- 主辦本人保有查看／編輯；既有已報名者保留本人紀錄、票證／取消與明細，不因此取得名單或新報名權限。只有主辦可修改可見性，官方活動另保留平台管理員既有管理權。
- 原有後台活動 migration 預設 `network`，原有會員辦活動預設 `platform`，不批次公開或下架既有活動。舊客戶端新增省略欄位沿用原預設；修改省略欄位保留現有值。
- 新歸屬活動採建立時已驗證的歸屬網，後續修改不藉此搬移活動。舊會員活動第一次選「歸屬」時設定主辦的已驗證歸屬。
- 梯次繼承同一活動的範圍、主辦與歸屬；舊獨立子梯次以父活動範圍為準。防重送 ID／requestKey／revision 和既有容量／截止／核銷規則不變。
- 權限或資料庫／migration 不可用時，不轉送舊後端繞過新範圍，不假報儲存成功。公開結果亦不信任客戶端角色。
- 本次僅實作與本機測試；正式 migration、Worker 與前端部署須另經使用者指示。
