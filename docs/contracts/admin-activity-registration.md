# Admin 活動報名與簽到管理

- 2026-09-28：依使用者要求，把既有活動監控整理為活動報名管理頁，參考福委會的分區方式，不匯入其資料。
- 沿用 `admin.html` 登入與 `getAllActivities`、`getActivityRegistrants`、`toggleCheckin`、`confirmPayment`。保留原本活動編輯、複製、上下架；不新增會員、點數、活動或報名資料表。
- 管理列表使用既有已驗證管理員 API，不退回公開 API。活動搜尋、歸屬網、上架狀態與日期篩選均作用於該 API 已授權回傳的資料。
- 選定活動才讀取其報名者，請求必須攜帶非空 activityId。切換活動後遲到的舊回應不得覆蓋目前名單。
- 報名資料以實際狀態為準；取消者不列入有效／已簽到／待付款統計，且不能簽到或確認繳費。`已付款`／`已繳費` 均視為已付款。
- 未載入人數顯示「查看名單」，不可把缺少的報名人數當作 0。空資料與載入失敗分開顯示。沿用 API 500 筆限制，達限制顯示提示，統計／匯出說明為已載入資料。
- 單筆手動簽到／取消簽到／確認繳費沿用手機 API。送出時鎖定操作，錯誤／逾時不自動重送 toggle；必須重新讀取成功後才允許再操作。
- CSV 僅匯出目前選定活動與篩選結果，保留文字電話及防公式注入；所有名稱／說明／回傳值安全轉義。
- 窄螢幕控制列換行、表格只在內部橫向捲動；返回活動列表、重新整理、匯出控制保持可見。
- 不改手機流程、現有驗證／權限、正式資料、秘密、點數／NFC 發點或福委會；Worker 僅可新增下述 AI 草稿 action，不改既有行為。
- 2026-09-28 補漏：活動總覽上方必須提供「＋新增活動」，使用手機端既有 `bulkAddRegistrants`，只建單一活動（`names: []`），歸屬及操作者沿用既有驗證。
- 新增表單可填名稱、類型、起訖、費用、說明、宣傳圖／版型與上架狀態。時間、金額、圖片網址須驗證；提供可見取消／關閉。此補漏不涉及系列梯次、匯入名單、獎勵點數或編輯 API。
- 每張新增表單配置唯一 activityId。送出時鎖定按鈕及欄位，失敗／逾時保留相同 ID 與快照，人工重試同一筆，不自動送第二筆；未確認成功不得顯示已建立。圖片上傳未完成或失敗時不可建立。
- 建立成功才關閉表單、清除列表篩選並重新讀取；取消未送出的表單不寫活動資料。既有編輯、複製、上下架與報名名單行為不改。
- 2026-09-28 AI 補漏：依福委會活動 DM 流程，選圖、AI 辨識、預覽草稿、套用並人工確認，再沿用既有建立 API。使用者已同意沿用現有 OpenAI 金鑰。
- `extractActivityDmDraft` 只接受後端已驗證 admin/store；沿用 manager policy、LINE token 驗證及 AI 限流，不相信 payload role 或金鑰。不寫活動／報名／點數資料。
- AI 僅接受 4 MB 內 JPG/PNG/WebP data URL，驗證內容 signature，禁止代抓任意遠端網址。請求有逾時、回傳欄位白名單與長度限制；日期／費用不明留空，不能默認免費或自行補日期。
- AI 草稿先預覽，套用前如已有手動內容須確認覆蓋；套用後仍可修改，且必須勾選確認日期、費用及內容才可提交。AI 失敗不清空原資料、不上架、不自動重送。更換圖片清除舊草稿預覽。
- 地點保留在既有活動說明，無新增資料表或 migration；不移植福委會購物、住宿或其資料。金鑰只在後端使用，不回傳 AI 供應商錯誤原文。
- 2026-09-28 報名短網址入口：後台「編輯活動」上方顯示唯讀報名短網址，提供複製／另開報名頁。沿用既有 createActivityShareLink 與已驗證管理員身份，不改活動編輯、儲存或報名資料。
- 下架活動不產生連結，提示先上架；短網址失敗可手動重試，等待期間停用連結操作，不使用其他活動的舊連結。關閉、切換活動或身份／token 變更後不可套用遲到結果；不得清空或自動儲存手動編輯內容。
- 2026-09-28 DM 核心欄位：辨識優先忠實擷取活動名稱、活動時間、活動地點（含地址／樓層）與活動說明，不強制產生摘要／亮點／行銷文案。沿用單次既有 AI 呼叫與金鑰，不新增 OCR 供應商。
- AI 回傳活動時間原文 scheduleText 與 single / multiple / unclear 的 timeStatus；只有明確單一場次且原文存在才帶入合法的開始／結束時間。多場次、日期不完整或不明時留空並提示人工選定，全部時間原文保留，不以報名截止日或報到時間取代活動時間。
- 核心欄位缺漏及不合法時間由後端補上人工確認提示。草稿預覽先顯示四項核心資料及時間原文；表單提供可修改的地點欄位，與時間原文透過既有 description 儲存，不增加資料欄位。套用須確認覆蓋，修改任何欄位須重新確認，建立／重試／權限流程不變。
- 2026-09-28 追加（取代上述僅單場限制）：新建／編輯提供明確重新辨識入口，失敗不改原表單；編輯需先預覽再確認套用，關閉或切換後不接受舊回應。原圖 CORS 不允許讀取時可重選檔案，不由 Worker 代抓任意 URL。
- 多時段回傳最多 24 個 batches 候選（名稱、原文、起訖、費用）；未知日期時間／費用留空。管理員逐項勾選並補齊後沿用 bulkAddRegistrants 的 isBatch / batches。保留單場模式；切換模式需明確操作。
- 系列使用現有 activities.is_series / series_id / batch_name / batch_limit 與 registrants；原子建立、穩定 ID 防重試重建。既有系列編輯不得清除系列旗標或改報名結構；重新辨識多場可明確另建系列，不自動轉換原活動／報名。
- 報名頁提供梯次多選，每梯次生成既有報名紀錄；後端核對 token、父子歸屬、上架與名額，以資料庫價格為準，重試不重報。同一系列及所選梯次於交易內確認並寫入，不回退舊後端吞掉梯次選擇。
- DM 草稿交接不得因候選缺漏時間／費用而無法開啟另建系列表單；保留空白供補填，僅正式儲存時強制驗證。套用本活動限勾選一場；多場須明確另建系列。操作提示放在按鈕旁並捲至可見，多場無候選時提供手動新增梯次，不猜測時間。原圖變更後拒絕套用舊草稿。
- 2026-09-28 使用者澄清（取代上述「編輯另建系列」入口）：多梯次必須共用同一活動、同一報名網址與同一張複選報名表。Admin 總覽將已授權載入的同網父子資料整理成一筆活動，梯次只作為該活動的附屬資訊，不平鋪為獨立活動；以梯次名稱或日期仍能找到所屬活動。缺少父資料或不同網的紀錄不得被靜默隱藏。
- 編輯 DM 移除「另建系列」流程；既有多梯次活動重新辨識只套用共用內容，保留原梯次、報名網址和報名紀錄。新增活動表仍可一次建立多梯次共同報名表。本次僅改 Admin 呈現及編輯引導，不刪資料、不重建活動、不修改梯次與報名 API。
- 2026-10-06：後台編輯將既有「活動類型」明確呈現為「活動分類」；可點活動／課程／聯誼／其他，也可沿用既有自訂分類或填1–40字。仍使用 updateActivity 的「活動類型」欄位，不新增欄位、活動或分類資料表；保留同一活動ID、梯次、報名、DM與歸屬。選分類不自動儲存，AI套用後再選分類須重新確認；儲存錯誤不關閉表單或假報成功。
