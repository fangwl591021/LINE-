# CRM 個人編號契約

- YYYYMMDD＋最少三碼流水號，以台北日界，20261021001 表示2026-10-21配號日第1號。新建會員為當日加入順序；重試、更新資料不重編；不同人不得撞號；已發號碼不回收。
- 編號由 D1 INSERT trigger 在會員建立的同一交易產生，涵蓋註冊、認領、同步、店家邀請與錢包索引建檔。不是 token／UID；不得用它登入或操作點數。
- 舊會員依可解析的 users.created_at（D1 UTC）補編，時間相同以 row_id 穩定排序，明示是歷史建檔補編、非原始精確加入順位。無效／未來日期不得假造加入時間；使用補編日發號，顯示日期待確認。
- users 附加欄位只能由號碼簿投影；一般及 admin profile payload 均忽略 memberNumber/memberJoinedAt。CRM 的資歷以唯讀權威日期計算，不以可修改 joinedAt 或編號前8碼推估未知日期。
- 既有身分合併仍只由既有明確確認流程執行；canonical 會員若已有號碼保留，舊號可經已持久化 active identity link 解析到 canonical 會員。不得由姓名／電話／編號自行建立身分連結。
- CRM 列表、搜尋、詳情顯示本人編號、日期來源與資歷；推薦人欄接受原UID或個人編號，編號須解析為唯一現存 canonical user，再沿用既有 admin-only 覆寫閘門。未知、自推、歧義不得寫入推薦；已有歸屬的普通會員不可藉編號改歸屬。
- 推薦人預覽 admin-only、token 驗證，僅回姓名／號碼／日期來源，不回電話／私有名片；預覽純讀、不發號、不註冊、不改推薦。
- 測試涵蓋台北跨日、同日順序與1000號、並行／重試、歷史無效日期、刪除不回收、身分alias、偽造欄位、權限／自推／未知號碼、CRM輸入競態與320/390/1280版面。
