# LIFF 路由契約

本文件定義 LIFF 與網頁路由的用途。路由必須先分類，再決定能不能寫入資料。

## 路由類型

### View Route

用途：只顯示資料。

允許：

- 讀取名片。
- 顯示網頁版名片。
- 顯示列表。

禁止：

- 寫入使用者資料。
- 改變名片歸屬。
- 改變目前發送版型。

### Edit Route

用途：編輯目前使用者可編輯的資料。

允許：

- 使用 LIFF 身分解析目前 UID。
- 載入目前 UID 的個人名片。
- 儲存按鈕後才寫入資料。

禁止：

- 頁面載入時自動寫入。
- 用 `ref`、`net`、`shareCardId` 覆蓋 owner。
- 抓不到名片時 fallback 到其他人的名片。

### Send Route

用途：在目前聊天室直接發送名片。

允許：

- 在 LINE 聊天室內使用可用 scope 發送訊息。
- 發送目前 UID 的指定名片版本。

禁止：

- 開啟通訊錄選擇器。
- 改變名片資料。

### Share Route

用途：讓使用者選擇好友或群組分享。

允許：

- 使用 `shareTargetPicker`。
- 分享指定的 Flex 名片。

禁止：

- 進入首頁。
- 跑好友檢查或註冊檢查。
- 顯示空白首頁。

### Web Route

用途：在一般瀏覽器顯示完成品名片。

允許：

- 顯示公開可讀的完成品名片。
- 顯示按鈕。
- 提供分享入口。

禁止：

- 呼叫需要 LIFF scope 的 API。
- 要求 LINE token 才能看公開名片。

## 重要參數

### `a` / `activityId` 活動報名直達（2026-09-28）

- 純活動連結（含 act/event 舊別名及 liff.state）直接進入活動等待／明細頁，不先顯示首頁、不讀首頁快取、不等首頁 14 秒的活動清單排程。
- 沿用 LINE 初始化、登入、好友檢查、checkUser；伺服器確認會員狀態後，以既有 getActivityById 讀單一活動。未註冊但已登入者沿用既有未註冊 session，不自動註冊或恢復名片綁定；查詢失敗不可假裝未註冊。
- 保留分享、認領、NFC、店家、管理頁、私訊等混合路由的原優先權；不符合純活動白名單不得走捷徑。
- 明確的 net/n（包含 admin）是活動顯示範圍；ref/r 只作既有推薦歸因，不能覆蓋明確的活動網路或目前會員身分。後端仍檢查可讀權限。
- 僅接收同一 ID 且上架的活動；下架、查無、網路錯誤或 15 秒未完成顯示重試／返回，不退回清單猜測、不自動報名。離開、切帳號或重試後的舊回應不得接管頁面。
- 讀取成功才呼叫既有 openActivityDetail；joinPublicActivity 仍只由使用者按下「我要報名」觸發。原報名、費用、點數、NFC 流程均不改。返回後不可因舊網址再次自動彈回活動。

### `memberChat`

會員私訊通知的 View Route，僅含不透明對話 UUID。完成既有 LINE 登入及會員驗證後開啟私訊，後端再次確認為對話當事人。沒有授權資訊、UID、點數或自動傳訊。與分享、認領、店家、活動等路由參數混用時不接管路由；非私訊入口不匯入通知路由模組。

### `shopSection=manage` 純管理入口

僅純管理路由及 LINE 登入傳輸參數可預載商城 JS/CSS。預載不能 mount 管理頁、讀取私有 API 或建立會員權限。LINE、好友與 checkUser 仍完成後才開啟管理頁，後端再驗證權限。會員查詢期間顯示無私有資料的管理等待畫面；不先讀首頁快取或觸發首頁資料。會員查詢失敗保留明確錯誤與重試。分享、認領、邀請、商品與簽到等混合路由不使用此捷徑。

### `shopProduct`

僅帶商品 ID。既有 LINE 登入與註冊驗證後開啟商品扣抵畫面；不從 URL 取得操作者或顧客 UID，不自動扣點。商品權限由後端重新查核。分享、認領等既有專用路由維持原本優先順序。

### `shareCardId`

用途：分享既有 Flex 名片。

規則：

- 只走分享流程。
- 進入後立即準備分享。
- 不進首頁。
- 不做點數通好友檢查。

### `webCardId`

用途：顯示完成品網頁名片。

規則：

- 可在瀏覽器開啟。
- 不可要求 LIFF token。
- 找不到名片時顯示明確錯誤。

### `share=1`

用途：表示外部分享或網頁展示模式。

規則：

- 不自動寫入資料。
- 不自動更換使用者身分。

### `mode=wysiwyg-card`

用途：進入所見即所得名片編輯器。

規則：

- 必須以目前 LIFF 使用者 UID 查自己的個人名片。
- 可用 `cardId` 指定自己的名片。
- 若 `cardId` 不屬於目前 UID，必須拒絕編輯。

### `ref`

用途：推薦人或分享來源標記。

規則：

- 只能作為歸因。
- 不可作為目前登入 UID。
- 不可覆蓋名片 owner。

### `net`

用途：租戶或網路區域標記。

規則：

- 只能決定查詢範圍或顯示上下文。
- 不可覆蓋身份。

## Scope 錯誤處理

若出現 `The permission is not in LIFF app scope`：

- 顯示可理解錯誤。
- 不得留空白頁。
- 可提供複製網址或返回聊天室入口。
- 不得嘗試以其他使用者資料完成操作。

## 測試要求

每次改動 LIFF 路由前，至少檢查：

- `shareCardId` 只開分享流程。
- `webCardId` 可在瀏覽器看到完整名片與按鈕。
- `mode=wysiwyg-card` 只能編輯自己的名片。
- `ref` 不會改變目前登入者資料。
- token 缺失時，新用戶必要讀取不會被卡死。
