# 業績歸屬日期及獎金試算契約

此文件描述隔離副本目前實作，不代表已部署或已完成正式結算。日期登錄、人工排序與獎金試算均不建立對帳單、不確認成交、不核發或付款；原有建單、實際收款、成交確認及既有獎金紀錄不會被覆寫。

## 日期登錄

只有經既有身分與權限驗證的總管可逐筆查詢、登錄、修改或撤回業績歸屬日期。日期可按月份、日期或台北時間精確到分鐘；只知道月份時不得補造日期。新增與撤回皆以事件保存版本、前後值、原因、操作人與登錄時間，使用預期版本及唯一請求編號防止競態和重複提交。原付款時間及訂單建立時間保留。

符合狀態檢查的年費或續約訂單，在尚未產生成交確認、獎金交易或對帳明細前，即使已有訂單快照或已核對的資料，仍可修改或撤回；快照存在本身不代表簽署、推薦關係或資格已核實。取消、退款、其他不符狀態，以及已有成交確認、獎金交易或對帳明細者均鎖定，不在此直接修改。API 對日期回傳 `affectsSettlement: false`：登錄不會自動計入正式結算；既有流程遇有效登錄日期須待核，不得忽略日期直接按原月份處理。撤回後是否能回原流程仍須經既有規則及狀態檢查。

## 排序草稿與試算預覽

管理員可檢視分頁候選，依原始證據建立有版本及請求編號的排序草稿、輸入範圍與依據，並明確聲明已人工核對完整性。候選來源無法證明未登錄歷史訂單不存在，系統回傳 `completenessProven: false`；人工聲明不可被顯示成系統已證明完整。訂單未填歸屬日期時不得以建單或收款時間代填。儲存結果不明時須用原請求編號及相同內容重試或讀回，不能重建成另一筆草稿。

依使用者確認，推薦人自 **2026 年 10 月起重新計數**；試算資格基準歸零，不回改該時間之前的既有紀錄。現階段預覽限於資料、適用合約及資格可完整驗證的 115.10 版制度新約；`periodFrom` 須為 `2026-10`，並由後端檢查簽署、身分、推薦與上線關係、收款、合約、服務開通、金額、排序範圍、既存交易及相關時間等資料。未通過整批相關檢查、資料缺失、存在既有處理影響、跨制度或續約等狀況維持待核，不應推算數字或聲稱通過。

後端同時回傳 `status: preview` 與 `calculation.status: preview`，且逐筆資料完整、無待核原因時，介面才顯示受領人、獎金類型、試算金額、順序及預估對帳截止時間（台北時間）。既存獎金紀錄須標明為既存資料，不能與本次試算混淆。缺件或異常數值以紅字說明待核；待核不得顯示臆測金額。預覽始終 `canConfirm: false`，截止時間僅為預估，不代表對帳單存在或任何付款。

## 發布界線

`0089_bonus_release_control.sql` 建立發布控制事件表；事件表為空時視為關閉。關閉時日期及排序草稿的 GET 保持可讀，POST 回傳 `503 FEATURE_DISABLED`；寫入時亦於資料庫條件再次檢查開關，避免檢查後被關閉仍寫入。介面須說明功能暫未開放；排序若曾有結果不明的送出，須保留原批次、內容及請求編號，不可因關閉而重建重複草稿。開關由經既有權限驗證的總管透過控制 API 以版本、原因與請求編號記錄，不能將 schema 遷移或發布本身視為啟用。

以上能力只在隔離副本實作與合成資料測試，不得宣稱已部署、完成正式月結或已發獎金。發布前需完成相應前後 guard、身分與競態檢查、完整整合及正式環境驗證。曾遭自動審核拒絕的完整檔案不得換管道、改名或以新路由繞過審核及既有權限保護。
