# 點數帳本契約

本文件定義點數讀寫規則。點數必須以帳本事件為準，不可用畫面值直接覆蓋。

## 受保護流程

- 店家點數收銀流程已固定在 `docs/contracts/store-point-cashier-protected-flow.md`。
- 後續除非使用者明確同意，不得修改該流程的查詢、收銀通道、送出與 fallback 行為。

## 身分來源

點數查詢優先順序：

1. `point_line_id`
2. `line_uid`
3. 舊系統橋接欄位

規則：

- 母站與子站必須橋接到同一個點數身份。
- 舊 LIFF 或舊系統留下的 UID 不得覆蓋目前 LINE UID。
- 顯示點數時必須使用同一個 canonical identity。

## 帳本事件

每筆客戶點數異動都應寫入事件：

- `eventId`
- `userId`
- `pointIdentity`
- `type`
- `amount`
- `beforeBalance`
- `afterBalance`
- `source`
- `createdAt`
- `operatorUid`

禁止：

- 不得只改總餘額。
- 不得沒有事件就改客戶點數。
- 不得讓前端自行計算最終餘額後覆蓋後端。

## 免費操作與免費傳送

以下操作不再扣店家或操作者的 `gift_money` 點數：

- 發送一般訊息。
- 發送優惠券。
- 發送課程邀約。
- 發送一對一訪談邀請。
- 店家消費贈點或消費折抵交易操作。

規則：

- 免費的是操作費與發送費。
- 客戶消費贈點仍必須增加客戶點數並寫入帳本。
- 客戶消費折抵仍必須扣除客戶點數並寫入帳本與收銀紀錄。
- 優惠券仍只能核銷一次。
- 新操作不得產生操作者 `-10` 或失敗退回 `+10` 事件。

## 消費折抵

### 交流刊登與私訊優惠券（2026-09-24）

- 交流刊登仍一次 10 點，但取消 7 天顯示與自動下架；既有 published 內容亦由作者自行管理，刪除／草稿不恢復。優惠券自身使用期限不變。
- 私訊附加本人有效交流優惠券免費，使用既有 coupon_handle，不複製券或新增點數流程。必須明確確認才核銷，沿用 exchange_zone_coupon_redemptions 每會員每券唯一限制；附件讀取／核銷需重新確認對話權限。

消費折抵不再使用固定 10%。

規則：

- 使用者輸入消費金額。
- 使用者輸入折抵點數或折抵金額。
- 系統計算應付金額。
- 店家交易操作免費，不另扣操作者點數。
- 折抵明細必須寫入帳本。

## 每日簽到

LINE 遊戲館的坦克守衛、方塊補給站與喵喵五子棋共用每日 100 點上限，沿用共用點數 API 與 point_awards，不更動簽到 10 點。保留既有 daily_tank_challenge 冪等鍵，防止舊前端與新遊戲各領一次。領獎、重送與跨站交易限制詳見 [遊戲館契約](game-center.md)。

規則：

- 每日只可領一次。
- 成功後顯示贈點結果，不顯示「已簽到」作為主按鈕文字。
- 簽到成功彈窗必須明確顯示「簽到成功」與獲得點數，不得誤用名片收錄成功文字；名片贈點仍保留名片提示。
- 按鈕狀態必須恢復，不得永遠停在 loading。

## 顯示規則

- 2026-09-20：本人點數紀錄整合母站與既有店家贈扣點／消費折抵明細，母站清單為空仍須顯示本人既有收銀明細。只有持久化身份映射可用於查詢，不以電話或姓名合併帳本；同交易只以交易編號／入帳 ID 去重，顯示清單不得用來重算餘額。
- 電話查詢須忽略電話內的連字號、空白與括號；會員儲存時移除相同分隔符。保留原有多會員同電話時拒絕自動選定的保護，不因格式清理改變 UID 或歸屬。

- 點數可能為負數，但 UI 不得破版。
- 長數字必須縮小或換行。
- 手機版不得蓋住姓名或 QR 區。
- 顯示格式不得自行加錯小數。

## 錯誤處理

若點數讀取失敗：

- 顯示可理解錯誤。
- 不得把點數顯示為 0 後寫回。
- 不得阻止新用戶必要流程。

## 測試要求

每次改點數前，至少檢查：

- 母站贈點後子站可讀。
- 發訊免費傳送，且不產生發送者扣點事件。
- 優惠券免費傳送，且只能核銷一次。
- 店家贈扣點工具仍存在，且操作免費。
- 客戶贈點與折抵交易雙方都能看到明細。
- loading 狀態會恢復。
