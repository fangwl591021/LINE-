# LINE OA 關鍵字契約

本文件定義 LINE OA 聊天室關鍵字的邊界。每一個關鍵字只能進入對應流程，不得順手改動其他資料域。

## 子站商城操作（2026-09-11）

- 精準文字「店家專區」「儀錶板」「儀表板」「商城業績」「商城商品」「商城訂單」由子站回覆，不取代母站其他關鍵字；不處理包含這些詞的自然語句。「商城商品／商城訂單」支援空格接頁碼 1–1000；保留這兩個指令前綴，錯誤頁碼直接提示、不轉發。
- 只在原 LINE 簽章驗證後接入。已認領事件（含無權限／失敗）不送往 GAS 或第二系統；混合批次只轉發其他事件並重新簽章，不遺漏其他事件。此規則只控制本 Worker 下游；上游母站不得另外回覆上述子站指令。
- 一對一聊天室依 source.userId 精準查 users.line_id；重複／未知身分拒絕摘要。群組只回覆私聊提示；standby 不消耗 replyToken。
- 店家專區：直接呈現本店商品；查商品、查業績、查訂單均使用 message 按鈕在聊天室回覆，不開網頁。一般會員只可查本人商品並提示一商品限制；店長／管理員可查本人業績和網購訂單。只有新增／編輯、核帳／出貨等變更操作保留網頁連結；連結不帶 UID、角色或認證 token，登入後重新授權。
- 僅店家專區及其衍生聊天室 Flex（商品、訂單與翻頁、業績、儀錶板、商城登入提示）統一 giga、xl 標題、lg 內文與操作文字；長文字自動換行，不限制行數。操作區可點擊 box 保留原 message／URI action 與順序。此樣式僅存在商城私有 card helper，不套用全域 reply/push 或 LIFF 傳送；我的電子名片、名片分享、活動、推薦 QR、自訂模板與其他非商城 Flex 全部維持原樣。
- 商品／訂單每頁 5 筆，SQL 僅取 6 筆判斷是否有下一頁；每次翻頁重新查角色及 owner_uid，不接受用戶指定其他 UID／店家。管理員查「我的」資料亦不跨店；只有儀錶板可彙總全商城。列表不 SELECT *，不取買家身分／聯絡／地址／銀行／完整訂單快照；商品名稱及訂單快照摘要有長度限制。無資料、無店家與讀取失敗須明確區分。
- 管理員儀錶板只顯示全商城聚合；店長只顯示目前自己店家的聚合。無會員／名片／聊天室監控內容，不公開購買者資料或銀行帳號。
- 今日現場商品 QR 折抵依台灣時間及成功確認紀錄計算，另列網購已核帳及待處理筆數；折抵後應收不等於銀行實收。不使用流水帳推估錢包、不扣點、不建立訂單。
- 不改 LINE webhook 網址、母站設定、交易開關、資料表或其他關鍵字。保留現有事件紀錄流程。
- 測試：test/store-line-keywords.test.mjs（已納入完整 smoke guard）。

### 聊天室儀表板直接多頁（2026-10-25）

- 「儀錶板／儀表板」直接回一則 Flex carousel，整合摘要與店家操作，不再要求先按「店家操作」才取得下一張卡。「店家專區」同樣以多頁呈現自己的商品與操作入口。
- 管理員的第一頁固定是「會員打卡設定」，直接提供「編輯會員打卡」到既有編輯器。管理員儀表板其餘頁為全商城摘要、本人店家操作；店長仍只看自己的摘要及操作。一般會員保留自己的商品管理入口及一商品政策，不開放營運摘要、訂單或業績。
- 所有頁使用既有商城 giga 樣式、合併於同一個 Flex 與一次 reply；不能由此觸發會員打卡或重送贈點。獨立商品／訂單翻頁、商城業績與原 SQL owner scope 維持不變。
- 編輯 URI 固定指向現有管理員頁，不攜 UID／token／角色；是否能讀寫模板仍由編輯器及伺服器的既有管理員權限決定。這個入口不擴權。

## 基本原則

### 會員打卡補送卡片（2026-10-19）

- 使用者明確接受母站原文字＋子站額外推播。原事件與 replyToken 仍交母站；子站只旁路觀察已驗證一對一「會員打卡」，不消費事件、不回覆、不重送母站、不贈／轉換點數。
- CHECKIN_MALL_CARD_ENABLED 控制補送；母站未設定、轉送失敗、standby、群組、舊事件及其他文字不補送。每則新的「會員打卡」事件均補一則多頁 Flex，即使母站表示今天已贈點也照常顯示。移除展示紀錄的會員／台北日唯一限制，保留真正台北日欄位及非唯一查詢索引；event_id 唯一鍵與 LINE retry key 防重，同事件重送不再查錢包／推播，未知送出結果不自動補推。
- 每個新事件建立自己的卡片 UUID、retry key、當次錢包查詢與最新已發布配置快照，不覆寫舊卡片／點擊來源。這項展示調整不變更母站每日贈點、點數轉換或原文字回覆。
- HTTP 成功不證明入帳；只查既有母站 gift_money 原始帳本，未確認本次交易時顯示「會員購物金」而不是打卡成功／固定新增金額。查詢失敗顯示無法取得，不顯示假零。卡片不含會員點數／轉換明細三行。
- 來源 UUID 不帶 UID、token 或權限。商城 LIFF 使用既有登入及註冊流程，伺服器驗證 token、channel／效期及實際開啟者。具名紀錄只在 POST entry 寫入 checkin_mall_clicks；GET／預覽／未登入不列入。同人同卡同按鈕一分鐘去重；計量為「已驗證進入」，不是實際按壓／已讀／購買。卡片告知記錄身分與時間。
- 點擊者報告僅現有權威管理員可讀，最多31日／每頁50筆；不開放店長、租戶、贈扣點角色或前端自稱管理員。無點數／個資／商品等變更權。API accepted 僅代表 LINE 接受推播。
- 測試：test/checkin-mall-card.test.mjs、test/checkin-mall-ui.test.mjs。

- 關鍵字必須先做文字正規化，再做精準比對。
- 一個關鍵字只能對應一個主流程。
- 顯示型關鍵字不可寫入資料。
- 匯入型關鍵字只能寫入自己的資料域。
- 任何關鍵字都不得用 fallback 抓到別人的名片。
- 若缺少資料，必須回覆下一步操作，不得自動建立錯誤資料。

## 我的名片

觸發文字：`我的名片`

用途：顯示目前 LINE 使用者自己的靜態專屬名片。

資料來源：

- 只能用目前事件的 `source.userId` 查詢個人名片。
- 只能查 `sourceType = self_profile` 的個人名片。
- 不得查 AI 名片夾、收錄名單、公開池或 admin 預設名片。

允許行為：

- 如果已有個人名片，推播靜態名片。
- 如果有多個靜態版型，提供版型選擇或使用目前發送版型。
- 如果沒有個人名片，提供建立名片入口。

禁止行為：

- 不得建立 AI 名片夾資料。
- 不得覆蓋影音名片。
- 不得抓其他 UID 的名片。
- 不得把掃描名片當成自己的名片。

## 影音名片

「人脈島」是使用既有影片名片編輯欄位的宣傳用途關鍵字，每位用戶可改自己的標題與說明；固定媒體及加入／分享流程依[人脈島契約](people-island-onboarding.md)。它不取代下列本人「影音名片」，不覆蓋video_profile，也不放寬一般影片上傳權限。事件在母站轉送前認領，保留單一reply owner。

觸發文字：`影音名片`

用途：顯示或建立目前 LINE 使用者自己的影音名片。

資料來源：

- 只能查目前 UID 的 `video_profile`。
- 影音名片是第四種版本，必須與靜態名片分離。

允許行為：

- 已有影音名片時，推播影音名片。
- 沒有影音名片時，啟動影音名片建立流程。
- 編輯完成後只更新影音版本。

禁止行為：

- 不得覆蓋標準、滿版、正方靜態名片圖片。
- 不得修改靜態名片發送版型。

## 重做影音名片

觸發文字：

- `重做影音名片`
- `重新製作影音名片`

用途：清除或重啟目前 UID 的影音名片草稿流程。

允許行為：

- 只重置影音草稿。
- 只影響目前 UID。

禁止行為：

- 不得刪除靜態名片。
- 不得清除 AI 名片夾資料。

## 名片酷 / AI名片夾

觸發文字：

- `名片酷`
- `AI名片夾`

用途：掃描或上傳別人的紙本名片，建立自己的收錄名單。

資料來源：

- 掃描者是目前事件的 `source.userId`。
- 建立的資料是收錄名片，不是個人名片。

允許行為：

- 詢問名片有一面或二面。
- 接收名片圖片。
- OCR 後開 LIFF 核對資料。
- 核對送出後建立收錄名片。
- 推播建立完成的電子名片。

禁止行為：

- 不得建立目前使用者的個人名片。
- 不得覆蓋被掃描者已認領的個人名片。
- 不得把自己掃到的名片放入公開池。

## AI名片夾：一面 / AI名片夾：二面

觸發文字：

- `AI名片夾：一面`
- `AI名片夾：二面`

用途：設定本次 OCR 流程需要上傳幾張名片圖片。

允許行為：

- 建立或更新目前使用者的 OCR 暫存流程。
- 回覆下一張應上傳的圖片提示。

禁止行為：

- 不得建立正式名片。
- 不得修改歸屬。

## AI名片夾：發送名片

用途：將剛建立或指定的收錄名片推播回聊天室測試。

允許行為：

- 讀取指定收錄名片。
- 推播該名片。

禁止行為：

- 不得變更 ownerUid、scannerUid、inviterUid。
- 不得把收錄名片改成個人名片。

## 推薦好友

觸發文字：`推薦好友`

用途：產生帶推薦人標記的 QR 或分享入口。

資料來源：

- 推薦人 UID 必須來自目前事件的 `source.userId`。

允許行為：

- 產生推薦 QR。
- 產生分享按鈕。
- 分享連結必須帶推薦人標記。

禁止行為：

- 不得改變目前使用者的個人資料。
- 不得把推薦人寫成被推薦人。
- 不得覆蓋名片歸屬。

## 測試要求

每次改動 LINE OA 關鍵字前，至少檢查：

- `我的名片` 不會顯示別人的名片。
- `影音名片` 不會覆蓋靜態名片。
- `名片酷` / `AI名片夾` 不會建立個人名片。
- `推薦好友` 不會修改使用者姓名、頭像、電話或名片 owner。
- 沒有資料時，回覆明確下一步入口。
