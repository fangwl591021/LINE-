# 共創夥伴新版制度

版本：`cocreator-2026-10-25-v2`。

依據使用者提供的《點數通共創夥伴推展合作契約書》，以及2026-10-25兩項明確決定：續約以第七條原推薦人25%＋當下歸屬人25%為準；新簽契約後的新成交才適用，舊訂單維持原規則。原文件SHA-256：`4b8fc61973e59c084e5c361c7b4da8f75b8d983bf53b06bde7dc2fe44f2c599c`。修訂副本另行交付，原文件不覆寫。

## 適用與核算

- 由平台管理員核對實際已簽新版文件，再從CRM「共創制度」登錄簽署、生效時間、文件SHA-256、保管參照及本人購買狀態。選取檔案只在本機計算SHA-256，不上傳文件，也不代替簽署。
- 實際登錄後、有效契約期間內新建的年度／續約訂單，才由伺服器擷取CRM推薦來源及契約版本並建立不可覆寫的訂單快照。舊訂單不轉版；前端傳入的制度名稱不能啟用新制。
- 一般夥伴累計兩筆本人直接推薦、已收款並經管理員確認開通的有效新制年度成交後晉升；第三筆起直接獎金50%。不以左右區或本人購買服務作為晉升條件。
- 如另有舊制已付款業績而歷史資格未核對，先待核，不把原有資歷推定為零，也不擅自回填舊業績。
- 前兩筆：本人已購買完整版時本人25%；本人未購買時其有效直屬推薦人承接25%。其餘25%依有效組織關係向上找第一位具進階資格者。無符合進階資格者由公司保留；必要事實或關係不能核對時整筆先待核。
- 續約：從原有效年度成交快照找原推薦人，再核對當下有同意證據的管理歸屬，各25%；同一人兼具兩種身分可合計50%。沒有原始成交或有效歸屬證據時不猜測受領人，不覆寫`users.referrer_id`。
- 以實收未稅服務費計算，全部獎金合計上限50%。6300元含稅／6000元未稅的25%為1500元，50%為3000元。
- 付款成功只更新付款紀錄；必須另外核對開通證據，才計入有效成交及產生獎金。撤銷／退費會停止有效業績認列；已支付流水保留，不自動重算其他歷史訂單。
- 文件的對帳、請款及給付天數仍有空白。新獎金一律`review_required`，不套用舊14天自動解凍，也不自動變成可支付／已支付。

## API與資料邊界

所有`/v1/partner-contracts`端點必須使用新鮮LINE登入憑證及平台管理員權限；寫入時再次核對目前管理員身分與角色。重試使用UUID requestKey，與資料庫併發鎖的內部隨機值分離。

| 操作 | 內容 |
| --- | --- |
| GET `?target=UID` | 已登錄契約、目前歸屬、有效新制成交數、待核訂單 |
| GET `/lookup?memberNumber=...` | 管理員以既有公開會員編號核對管理人 |
| POST 根路徑 | 登錄已實際簽署並核對的新版契約 |
| POST `/attribution` | 登錄有同意文件校驗碼及參照的管理歸屬沿革 |
| POST `/deals/confirm` | 核對已收款且開通的新制訂單、計算獎金，保留待核付款狀態 |

Migration0070只新增制度資料表，不回填契約、不修改既有訂單、獎金、推薦關係、角色或點數。既有左右區文件與引擎保留為舊訂單規則，不能把本頁解讀為所有歷史訂單已升級。

部署必須先套用0070，再部署Worker。新舊年度訂單的「新建」共用版本判定鎖，消除簽約與建單的競態；舊訂單ID重送只能唯讀回放，內容不同則拒絕覆寫。不得省略migration。

## 驗證

本機隔離SQLite及Workerd/D1測試涵蓋制度比例、授權、原始快照、舊訂單保留、重複送出、退款資格、併發確認；CRM瀏覽器測試涵蓋確認欄位、證據、無自動寫入及登入變更。正式環境只做集合統計與讀取驗證，不建立測試契約、訂單或獎金流水。
