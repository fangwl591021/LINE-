# 共創夥伴制度：115.10 與既有訂單版本

## 115.10 現行簽約制度

業務來源為使用者指定的《點數通共創夥伴推展合作契約書115.10版》，未簽原件 SHA256：`224dac420aba1f0990f5de713e7125c4d9699a6a11f84ee6aed6f8ddee7da4aa`。甲方為智點通股份有限公司，代表人楊滄棋。本頁不公開私密契約原件。2026-10-28 已新增獨立[線上手簽申請](reward-applications.md)，由本人簽署後送平台審核；此處的制度登錄仍須管理員核對已簽文件，不因送出或審核申請自動啟用獎金資格。

2026-10-29 新提供的115.10手簽來源 SHA256 為 `1fa48f76ed888e656a5e1efac84c670b1132f8f1cf6a62fa8c8c76b48ba7f42c`；第1至13條正文相同，更新甲方收款資料，線上表單依使用者指示繼續保留法人代表人欄。新舊來源指紋不代表個別已簽契約的來源：CRM僅在單筆有記錄時顯示該筆空白範本指紋，否則顯示未記錄。既有制度版本、契約及已簽文件指紋不改。

新政策版本 `cocreator-115.10-v3`、模板版本 `115.10`，與已簽文件 SHA256 分開保存。簽後文件 hash 不會等於未簽模板 hash。新登錄必須明確選版，不讓舊快取畫面默默建立錯版契約；歷史 v2 登錄只接受 2026-10-26 台北零時前已簽的文件。既有訂單、既有簽約與已付款流水保持原制度及快照。

使用者於 2026-10-26 明確裁定：

- 第十二條優先於第十條衝突文字：終止後取消新制度已成立而未支付的獎勵。已支付流水保留，系統不自動從銀行追回款項。終止事件含生效時間、書面證據、原因與操作者，不覆寫歷史。
- 年度門檻採每次檢查最近連續十二個月有效新約至少六件，排除續約與停止後重新加入。簽約未滿十二個月不提前判定未達年度義務；低於門檻列待處理，管理員可依證據取消，系統不自動停權。

### 簽約、獎勵及生命週期

- 契約自實際簽署日起生效，一年一期；未於當期屆滿三十日前登錄書面不續約通知，依原條款延長一年。一般終止至少提前三十日；重大違約或年度未達標須選明確依據及保管證據。
- 115.10 訂單只在契約登錄後新建時取得伺服器快照。已停止的 115.10 契約不可使新成交靜默退回舊制；重新簽約也不能復活舊契約終止時已取消的未付獎勵。
- 免費加入不以本人購買為條件。兩筆有效直接新成交晉升，第三筆起直接 50%；前兩筆及差額承接保留原有明確核算。實收未稅為基礎，合計上限 50%。
- 續約原推薦人 25%＋當下有同意紀錄的歸屬人 25%；同人可合計 50%。只有尚無法核對的部分暫停，已確認的另一部分可獨立對帳。補確認不得換付不符合原始推薦／歸屬證據的人，也不得重複建立同一部分。
- 管理員確認已付款、開通及完整服務年度後才認列；同商家重疊服務年度不可重複領獎。新約、續約、停止後重加入分開記錄；退款取消未付獎勵及待核部分，已支付流水保留。
- 原推薦、管理同意及 UID 不會因本制度而自動改寫。新登錄補記自然人／法人、代表人、簽約推薦會員編號核對及獎金銀行資料，限已授權管理員讀寫。

### 對帳、請款及付款紀錄

- 對已結束月份建立對帳快照，應於次月五日前提供。實際送達須有時間及證據，異議期限為收到後五個日曆日；逾期提供如實標示。
- 合法請款資料完整後十個工作日為給付期限；依[人事行政總處官方資料](https://data.gov.tw/dataset/14718)計算，目前收錄 2026、2027 年。未知年份回到待核，不自行用週一至週五猜算；更新來源須保留 hash 與年度完整性驗證。
- 爭議部分保留具體理由與處理期限，可分別釋放或取消。補確認部分採追加對帳，既有快照不覆寫、同一流水不重複列入。
- 付款功能只讓管理員登錄實際付款憑證，不會自動匯款。須完成請款、異議期及有效資格核對，未解決爭議、已終止及已退費部分不可支付；與舊月結選取分開。

### 新增 API

沿用 `/v1/partner-contracts` 的新鮮 LINE 登入、管理員權限、UUID 重試及共用 CAS 鎖。增加 `/lifecycle`、`/renewals/resolve`、`/settlement` 與其 statements／claims／disputes／resolve／payments 操作；完整 payload 以 CRM 表單及伺服器白名單為準。GET 不建立契約、訂單、獎勵或推播。

部署先套用 additive migrations 0074、0075，再發布 Worker 及對應 Pages 快取版本。不得重寫舊資料或藉遷移批量簽約；保留實際未簽狀態。

## 既有 v2 制度（只適用原版本訂單）

版本：`cocreator-2026-10-25-v2`；以下描述保留既有訂單行為，不代表 115.10 的新條款。

依據使用者提供的《點數通共創夥伴推展合作契約書》，以及2026-10-25兩項明確決定：續約以第七條原推薦人25%＋當下歸屬人25%為準；新簽契約後的新成交才適用，舊訂單維持原規則。原文件SHA-256：`4b8fc61973e59c084e5c361c7b4da8f75b8d983bf53b06bde7dc2fe44f2c599c`。修訂副本另行交付，原文件不覆寫。

## 適用與核算

- 由平台管理員核對實際已簽新版文件，再從CRM「共創制度」登錄簽署、生效時間、文件SHA-256、保管參照及本人購買狀態。選取檔案只在本機計算SHA-256，不上傳文件，也不代替簽署。
- 實際登錄後、有效契約期間內新建的年度／續約訂單，才由伺服器擷取CRM推薦來源及契約版本並建立不可覆寫的訂單快照。舊訂單不轉版；前端傳入的制度名稱不能啟用新制。
- 一般夥伴累計兩筆本人直接推薦、已收款並經管理員確認開通的有效新制年度成交後晉升；第三筆起直接獎金50%。不以左右區或本人購買服務作為晉升條件。
- 如另有舊制已付款業績而歷史資格未核對，先待核，不把原有資歷推定為零，也不擅自回填舊業績。
- 前兩筆：本人已購買完整版時本人25%；本人未購買時其有效直屬推薦人承接25%。其餘25%依有效組織關係向上找第一位具進階資格者。無符合進階資格者由公司保留；必要事實或關係不能核對時整筆先待核。
- 續約：從原有效年度成交快照找原推薦人，再核對當下有同意證據的管理歸屬，各25%；同一人兼具兩種身分可合計50%。沒有原始成交或有效歸屬證據時不猜測受領人，不覆寫`users.referrer_id`。
- 以實收未稅服務費計算，全部獎金合計上限50%。6300元含稅／6000元未稅的25%為1500元，50%為3000元。
- 付款成功只更新付款紀錄；必須另外核對開通證據，才計入有效成交及產生獎金。撤銷／退費會停止有效業績認列；已支付流水保留，不自動重算其他歷史訂單。
- 文件的對帳、請款及給付天數仍有空白。新獎金一律`review_required`，不套用舊14天自動解凍，也不自動變成可支付／已支付。

## API與資料邊界

所有`/v1/partner-contracts`端點必須使用新鮮LINE登入憑證及平台管理員權限；寫入時再次核對目前管理員身分與角色。重試使用UUID requestKey，與資料庫併發鎖的內部隨機值分離。

| 操作 | 內容 |
| --- | --- |
| GET `?target=UID` | 已登錄契約、目前歸屬、有效新制成交數、待核訂單 |
| GET `/lookup?memberNumber=...` | 管理員以既有公開會員編號核對管理人 |
| POST 根路徑 | 登錄已實際簽署並核對的新版契約 |
| POST `/attribution` | 登錄有同意文件校驗碼及參照的管理歸屬沿革 |
| POST `/deals/confirm` | 核對已收款且開通的新制訂單、計算獎金，保留待核付款狀態 |

Migration0070只新增制度資料表，不回填契約、不修改既有訂單、獎金、推薦關係、角色或點數。既有左右區文件與引擎保留為舊訂單規則，不能把本頁解讀為所有歷史訂單已升級。

部署必須先套用0070，再部署Worker。新舊年度訂單的「新建」共用版本判定鎖，消除簽約與建單的競態；舊訂單ID重送只能唯讀回放，內容不同則拒絕覆寫。不得省略migration。

## 驗證

本機隔離SQLite及Workerd/D1測試涵蓋制度比例、授權、原始快照、舊訂單保留、重複送出、退款資格、併發確認；CRM瀏覽器測試涵蓋確認欄位、證據、無自動寫入及登入變更。正式環境只做集合統計與讀取驗證，不建立測試契約、訂單或獎金流水。
