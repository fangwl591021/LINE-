# LINE- 影音製作

## 開始前讀取

- 調整介面、名片或影片版型時，讀 [DESIGN.md](../../../DESIGN.md) 的相關元件規格；不要將某一張卡片尺寸套用到所有名片。
- 涉及人物業務介紹，讀 [名片業務說明契約](../../../docs/contracts/card-business-description.md)。
- 涉及人脈島加入、參觀、註冊或交流，讀 [人脈島契約](../../../docs/contracts/people-island-onboarding.md)；影片不得教出可繞過資格檢查的流程。
- 需要改程式或發布時，接 [發布驗證技能](../line-release-verification/SKILL.md)。只產出本機影片時，依媒體驗收完成，不額外要求整套程式發版。

## 先確定影片要說明什麼

辨認使用者要的是操作教學、宣傳介紹或既有影片修訂；沿用已確認的範圍、角色與發佈位置。
先查現行入口、按鈕與狀態變化，流程教學應涵蓋開始操作、必要輸入、確認、結果及返回入口。
修訂現有影片時先找可編輯來源；除非需求涉及旁白、字幕或流程，不重做其他內容。
手機展示預設採直式構圖與繁體中文；旁白、字幕、比例、長度及卡片尺寸依使用者需求與元件規格決定，不能把既有 45 秒影片當所有影片的固定規格。

## 人物與業務必須一致

1. 以使用者提供的本人名片／資料，以及可讀取的官網、官方社群或可核對的公開來源確認同一人物與公司。
2. 將姓名、公司、業務標題／職稱、實際服務與來源整理為同一份人物資料；畫面名冊、彈窗、字幕及配音從這份資料產生或逐一比對。
3. 改姓名時同時檢查公司、職業與服務；不要只替換姓名後留下示範職業。真人只對應已確認的資料，不放進會輪換其他公司或職業的示意姓名陣列。
4. 歷史活動的職稱不直接當成現職；公司登記項目、網址字樣或模型推測不等於實際服務。來源不足時保留可確認內容，明示缺口，不補造證照、成果、客戶或頭銜。
5. 把使用來源、核對日期、支持的欄位與限制記入本機 `source-evidence.json`。搜尋索引可讀而原頁不可讀時標明索引來源，不宣稱已讀原文。

先查已有資料及可取得的公開來源；仍無法唯一辨認同名人物或確認本次必要業務時，才向使用者補問最少線索，例如公司、名片或本人連結。可繼續準備場景與其他段落，釐清前不發布含未確認業務的人物介紹；這是補齊資料，不是重新要求已給過的發布許可。

只把必要身分線索用於公開業務交叉核對，遵守既有契約的個資範圍；不把私人標籤、生日或會員 UID 加入搜尋或影片。

## 錄影與畫面

- 優先呈現現行介面的實際操作與正確角色；示意資料、合成帳號及模擬畫面清楚標示。
- 對話、點數、訂單等流程以隔離資料或攔截請求驗證。正式帳號／真實訊息測試依使用者已授權範圍執行，並記錄實際副作用；不因拍片擴大權限。
- 保持讀取、確認與送出狀態清楚；載入中、取消或失敗不能剪成成功結果。
- 檢查小螢幕文字、操作按鈕、字幕與彈窗是否完整可見；字幕不能遮住本次要教的控制項。
- 使用有權使用的圖片、影片、聲音及字型，人物資料與版型修改限於本次需求。

## 輸出與驗收

依目標平台選擇編碼；既有手機網頁／LINE 影片通常沿用 H.264、AAC、可串流 MP4，仍須核對現行平台要求及原規格。

- 讀取成品的實際解析度、比例、長度、幀率、音訊與檔案大小，完成整片解碼檢查。
- 檢查旁白可聽清、字幕與畫面時序，以及有無多餘空白、灰色補邊、裁切或結尾截斷。
- 擷取開頭、關鍵操作、人物介紹與結尾等代表畫面，實際查看編碼後的成品；修改處必須有可核對的畫面證據。
- 對照人物資料及來源檢查每次出現的姓名、公司、職業與服務，特別檢查既有示範文案是否殘留。
- 操作教學同時驗證完成後的狀態及入口可繼續使用；影片展示成功不能代替功能測試。

保留成品、封面、使用到的字幕／逐字稿、可編輯來源與必要資產、SHA256 及媒體 QA 紀錄。來源與中間產物放在不會被網站整包發布的位置；實際路徑寫入本次工作單，不在此技能寫死個人電腦目錄。

## 發布與交付

使用版本化的新媒體網址及匹配封面，依 [發布驗證技能](../line-release-verification/SKILL.md) 更新引用與快取版本，讀回公開檔案並驗證播放。
已發出的 LINE 訊息不會因前端更新而改變；需要新卡片時說明重新分享，測試不得自行向真人發送。
影片發布授權不包含公開可編輯來源或來源 ZIP；來源預設留本機，只有使用者授權公開來源時才發布來源包。
沿用使用者已給的部署與測試授權，不新增重複確認關卡。

交付時說明可用入口、改了哪些內容、媒體／功能／線上播放各通過哪些驗證，以及仍未做的手機 LINE 實收驗收。若未部署，清楚標示本機成品與狀態。
