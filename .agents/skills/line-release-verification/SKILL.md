# LINE- 發布驗證

將已要求的變更發布到正確服務，留下可以重查的版本與驗證證據。本技能不新增部署、發訊、交易或資料修改權限；沿用本次需求及既有授權，已授權測試通過直接部署時不要再設確認關卡。

## 確認範圍與來源

從 Git 根目錄執行，核對 remote、分支、工作區變更與最新主分支，保留非本任務內容。閱讀[變更流程](../../../docs/release/feature-change-protocol.md)與本次功能契約；功能修改依原流程先跑 before guard、建立工作單，再修改及跑 after guard。檢查失敗先修復，不發布失敗版本。

依實際交付選擇需要的部分：

| 變更 | 發布／核對來源 |
| --- | --- |
| 前端 HTML、JS、CSS | [Pages 工作流程](../../../.github/workflows/deploy-pages.yml)、實際線上頁面及所有入口的載入版本 |
| Worker | [wrangler.toml](../../../wrangler.toml)、其 main 入口與 import，核對帳戶、環境及現行綁定 |
| 影片、封面等媒體 | 前端引用的實際 R2 網域、bucket／key 與內容類型；不要從檔名猜資源 |
| AGENTS／DESIGN／技能／一般文件 | 核對內容、相對連結及技能格式，透過 Git 保存；若現行主分支工作流程自動更新 Pages，核對該流程，不另外部署 Worker 或操作資料 |

Windows 使用可用的 `npm.cmd`／`npx.cmd` 或已確認的執行檔。依專案現有版本及 CLI help 查核指令，不為了部署順帶升級工具。

## 完成測試

- 功能改動的具體指令、停止條件與工作單格式以[變更流程](../../../docs/release/feature-change-protocol.md)為準。只更新因核准規格變更而受影響的檢查，不降低無關保護。
- 選擇能驗證實際結果的檢查：例如編輯→儲存→重開、取消與失敗、切換帳號後的舊回應隔離，以及手機上入口仍可找到。不要只核對第一張畫面或字串。
- 合成帳號與攔截 API 可驗證流程；不得把它記成真人 LINE、正式扣退點或真實交易驗收。實帳號驗收須在本次已授權範圍內，記錄前後狀態、結果與必要清理，不能自行擴張測試副作用。
- 影片先依[影音製作技能](../line-media-production/SKILL.md)完成內容、播放與畫面核對，再發布媒體。

## 依範圍發布

### Pages／前端

更新被修改檔案的必要快取參數，檢查 HTML、動態 import、獨立預覽等實際入口使用同一版本。建立只含本次變更的 commit／PR，合併前等待必要 CI 通過，再確認 Pages 部署的 commit 與結果。建立 PR 後，在工具可用時附加到當前工作；工具不可用則保留連結，不刪除其他附件騰空間。

只有前端或文件變更時，不重新發布 Worker。注意[目前 Pages 工作流程](../../../.github/workflows/deploy-pages.yml)上傳整個儲存庫，不把私密證據、金鑰、正式會員資料或僅供本機保存的可編輯來源放進發布目錄。

### R2 媒體

先檢查 key 是否已使用。內容有變使用新版本 key；先上傳並讀回媒體，再發布引用它的前端。相同版本重試時比對內容，不任意覆蓋不同檔案。

核對 MIME、大小、SHA256 與需要的播放範圍／格式。可公開的完成影片與封面，並不代表可公開來源 ZIP；除非使用者指定公開來源，來源及詳細製作證據保存在本機交付位置。

### Worker

部署前核對 live 版本、必要設定、D1／KV／R2 綁定與排程，避免將不完整本機設定覆蓋正式環境。使用現有 Wrangler 版本支援的 dry-run／部署流程；需要保留 Dashboard vars 時核對 `--keep-vars`，它不代替綁定與排程核對。不得輸出金鑰明文。

不因這次發布自行新增 migration、輪替 secret、重建資源或切換母站權威。若本次就是修改這些部分，依該任務契約與授權處理。記錄發布後 active version；dry-run 成功不能代替正式執行結果。

## 正式版本驗證與交付

- 核對實際服務的檔案內容或雜湊與核准 commit 一致，避免只有部署成功卻仍讀到舊快取。跨 Windows／Linux 比對文字時可正規化 CRLF；二進位媒體逐位元比對。
- 在正式頁面檢查本次受影響的流程；媒體確認實際 currentSrc、比例、播放及有變更的時間點。不要為了驗證額外發送 LINE、建立會員或異動點數。
- 前端更新後核對原 Worker 版本未動；Worker 更新後核對必要設定與排程。取得不到證據時記錄限制，不能宣稱已確認。
- 留下 commit／PR、部署結果、正式網址、適用的媒體雜湊與驗證結果。對使用者簡要說明改了什麼、測了什麼、是否部署，以及手機實收等尚未驗收項目；既有 LINE 訊息不會回溯更新，需重新分享的變更要明示。
